# Baseline vs MCP — Side-by-Side Retrieval Browser

Pre-rendered side-by-side comparisons of the tool-call / retrieval history for
tasks where **Sourcegraph MCP beat the local-filesystem baseline** by a
meaningful score margin. Useful for understanding *how* MCP retrieval changes
agent behavior on tasks where it actually helps.

## What's here

- **`index.html`** — sortable table of every MCP win (delta ≥ 0.20) across
  every paired suite/model cell under `runs/analysis/`. Rows link to a
  rendered detail page when one is committed; otherwise the row notes that
  regeneration is required.
- **`wins_manifest.json`** — full manifest of MCP wins (one entry per task).
  Stable schema: `suite`, `model`, `task`, `slug`, `baseline_reward`,
  `mcp_reward`, `delta`, `baseline_trial_name`, `mcp_trial_name`.
- **`<suite>__<model>__<task>.html`** — rendered side-by-side compare page for
  the top 20 wins (highest delta first). Each page shows, for both baseline
  and MCP:
    - reward + headline metrics (time, cost, tokens, tool-call count, files
      modified)
    - tool-call breakdown by tool name
    - full tool-call list with input/output payloads
    - code changes (edit / write) and bash commands
    - conversation events

## Regenerate locally

The committed gallery is a 20-page subset. Anything in `wins_manifest.json`
that doesn't have an HTML page can be regenerated by running the generator
against your local `runs/analysis/` tree:

```bash
# Render the full set of wins (everything in the manifest)
python3 scripts/analysis/browse_compare.py \
    --threshold 0.20 \
    --render-all \
    --out browse/compare

# Or focus on a single suite/model cell
python3 scripts/analysis/browse_compare.py \
    --suite csb_org_security \
    --model cc_sonnet46 \
    --threshold 0.10 \
    --out browse/compare/security_sonnet
```

Outputs to `browse/` (gitignored) by default unless you point `--out` back at
this directory.

## How pairs are matched

For each `runs/analysis/<suite>/<model>/` cell with both `baseline/` and
`mcp/` subdirectories:

1. Each trial dir is parsed via `extract_task_data` (reuses the per-run
   browser's parser).
2. Trial names are canonicalized: config prefix stripped (`mcp_`, `bl_`,
   `sgonly_`), trial-id suffix stripped (`_XXXXXX` or `__XXXXXXXX`), then
   lowercased.
3. The highest-reward trial per side wins (handles MCP cells that have 3+
   trials per task).
4. A pair counts as an "MCP win" when `mcp_reward - baseline_reward >=
   threshold` (default 0.20).

## Broken-environment filter

Pairs whose **baseline** trial used ≥ 10 `WebSearch`/`WebFetch` calls and
≤ 5 local-file calls (`Read`, `Glob`, `Grep`, `Edit`, `Write`, `Bash`,
`str_replace_editor`, `execute_bash`) are **excluded by default**. These
typically mark a broken sandbox where the workspace mount failed, so the
baseline agent fell back to web search instead of touching local files —
any MCP "win" against that baseline is an artifact of the broken
environment, not a fair retrieval comparison.

Pass `--include-broken-env-baselines` to keep them (diagnostic only).

## Source runs

These comparisons are built from `runs/analysis/<suite>/<model>/{baseline,mcp}/`
— the local analysis runs used to back the technical reports under
`docs/technical_reports/` and the long-form report at
`docs/analysis/sourcegraph_baseline_vs_mcp_report.md`.

When `runs/analysis/` is not present locally, restore from NFS per
`runs/OFFICIAL_OFFLOADED.md` first.
